# 課題2の実装ステップ

## 1. AIと作業するための準備

- リポジトリ直下に `AGENTS.md` を用意し、参照資料、作業範囲、完了条件の確認方法を記載する。
- 生成コードを変更する場合は、OpenAPIやSQLなどの生成元を編集して再生成する方針を記載する。起動・テスト・コード生成のコマンドは、使えるようになった段階で追記する。
- **完了条件** `AGENTS.md` から要件と設計を参照でき、ステップごとの進め方が分かる。

## 2. 開発・テスト環境

- `compose.yaml` に開発用のGoサーバーを追加し、既存のMySQLと一緒に起動する。開発サーバーはHTTPで起動し、ソースをマウントしてAirで監視する。
- DBなしのユニットテストと、テスト用MySQLを使う `httptest` の実行環境を整える。機能ごとのテストケースは各ステップで追加する。
- リモートリポジトリを用意し、CIでユニットテストとGoコードのフォーマットチェックを実行する。
- **完了条件** `docker compose up` で開発環境が起動し、Goファイルの変更でAPIが再ビルド・再起動する。両方のテストをローカルで実行でき、CIでユニットテストとフォーマットチェックが通る。

## 3. API仕様とルーティング

- OpenAPIで `GET /students` のクエリとレスポンスを定義し、`oapi-codegen` でGin用のコードを生成する。ハンドラーを仮の取得処理につなぐ。
- **完了条件** `httptest` でレスポンスの形と、`facilitator_id` の欠落・型不正でメッセージ付きの `400` が返ることを確認できる。

## 4. MySQLから生徒一覧を取得

- `sqlc` でデータアクセスコードを生成し、ハンドラー、ユースケース、リポジトリ、MySQLをつなぐ。教師IDで絞り込み、クラス情報と `totalCount` を返す。
- テスト用MySQLを使うHTTPテストをCIに追加する。
- **完了条件** 初期データで `facilitator_id=1` を指定すると、生徒ID `1, 4, 7, 10` がID昇順で返り、`totalCount` が `4` になる。CIでユニットテストとHTTPテストが通る。

## 5. 検索

- `name_like` と `loginId_like` の部分一致を実装する。両方を指定した場合はAND条件にする。
- **完了条件** 各検索条件とAND検索をテストし、絞り込み後の件数が `totalCount` に反映されること、該当件数が0なら本文なしの `404` が返ることを確認できる。

## 6. ソート

- `sort` と `order` を実装する。既定値は `id` と `asc` とし、生徒名が同じ場合は生徒IDの昇順で並べる。
- **完了条件** `id`、`name`、`loginId` の昇順・降順、同名時の順序、不正なソート指定に対するメッセージ付きの `400` を確認できる。

## 7. ページネーション

- `page` と `limit` を実装する。既定値は `1` と `5` とし、`totalCount` にはページ分割前の該当件数を返す。
- **完了条件** デフォルトのページ分割、不正値に対するメッセージ付きの `400`、該当件数があっても指定ページが範囲外なら空配列と `totalCount` を含む `200` を確認できる。検索とソートを併用した場合も、絞り込んで並べた結果から指定ページが返ることを確認する。

## 8. 通常起動とHTTPS

- `compose.yaml` のAPIを静的ビルドしたバイナリの `scratch` 上での実行に切り替え、Airとソースのマウントを `compose.dev.yaml` に移す。
- ローカル用の自己署名証明書の自動生成とMySQLの起動待ちを組み込む。通常起動と開発起動でMySQLとTLSの設定を共通にする。
- READMEに起動、証明書を検証して接続する方法、テストの実行手順を記載する。
- **完了条件** `docker compose up` と開発用のCompose構成の両方で起動し、`curl --cacert` で `https://127.0.0.1:48080/students?facilitator_id=1` に接続できる。

- **完了条件** `teacher` が存在しないこと。
