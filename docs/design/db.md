# データベース設計

現在のDBの設計は[スキーマ](../../mysql/init/01-schema.sql)を参照してください。

## 生徒と教師の関係性について
今回はクラスを仲介して関係を持つように設計しています。
つまり、クラス担任が受け持つ生徒との関係を表しています。

個別指導など、別の形式の関係性を表す場合は、データベース設計を拡張する必要があります。

## `class_teachers` について
今回のデータのみを考えると不要ですが、以下のケースに備えて拡張しやすいようにしています。
- 1人の教師が複数のクラスを受け持つ
- 1つのクラスに主担任・副担任がいる

一方で、生徒は必ず1つのクラスに所属する想定でいます。
これは、一般的な日本の小中学校での形態に合わせています。
特殊な学校や、日本以外の地域の学校にも対応する場合、データベース設計を見直す必要があります。

## `student_accounts` について
今回のデータのみを考えると不要ですが、一般的にユーザ情報とログイン情報は分けて管理したほうが良いと考えています。
- ログイン情報はログイン関連でしか使用されないが、ユーザ情報はシステムの全般で使われやすい
- 複数のログイン手段を持つ必要がある際にサポートしやすい
- ログイン情報の誤出力を低減させる
