# 開発ツールの依存関係

oapi-codegen、golangci-lint、actionlint は、それぞれ `tools/` 配下の専用 Go モジュールでバージョンを固定する。

## 背景

golangci-lint と actionlint を同じモジュールに登録すると、両方が使う `go.yaml.in/yaml/v4` に対して一つのバージョンが選ばれる。導入時の golangci-lint v2.14.0 と actionlint v1.7.12 の組み合わせでは、選ばれた YAML ライブラリの API が actionlint の想定と異なり、ビルドに失敗した。

## 選択肢と採用理由

- アプリケーションの `go.mod` にまとめると、ツールとアプリケーションが同じ依存関係を使う。
- ツール共通の `go.mod` にまとめると、アプリケーションからツールの依存を分離できる。ツール同士の依存は共通になるため、今回の競合は解消できない。
- ツールごとに `go.mod` を分けると、各ツールに必要な依存関係を個別に解決できる。oapi-codegen にも同じ構成を適用し、アプリケーションの依存関係から分離した。

この構成では、ツールの追加や更新時に個別の `go.mod` と `go.sum` を管理する。リポジトリルートから実行する場合は `go tool -modfile=tools/<ツール名>/go.mod <ツール名>` で対象のモジュールとツールを指定する。
