# アーキテクチャの設計方針

全体の構成については、リポジトリのディレクトリ構成や [ARCHITECTURE.md](../../ARCHITECTURE.md) を参照してください。

## スキーマ駆動

スキーマと実装の乖離を防ぐため、主に次の 2 つのコード生成にスキーマ駆動を採用します。

- OpenAPI をもとに Gin のエンドポイントを生成します。
- SQL をもとにクエリ実行関数を生成します。

## フラットパッケージとレイヤードアーキテクチャ

対象となるドメイン領域が現時点であまり複雑でないことから、[フラットパッケージ](https://future-architect.github.io/articles/20201109/)を採用します。
記事で紹介されている方針のうち、「同じパッケージに入れる」という部分を採用します。

すべてを同じファイルに書くと煩雑になるため、レイヤーごとにファイルを分けて管理します。Go では可視性の制御がパッケージ単位になるため、レイヤー間の依存関係が適切かどうかは、レビューなどの開発プロセスで確認します。
